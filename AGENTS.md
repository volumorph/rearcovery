# AGENTS.md — инструкции для разработки

Проект: **Путеводитель по паролям** — офлайн-сейф паролей с маршрутами восстановления. Это инструкция для ИИ-агентов и разработчиков, которые будут изменять код. Подробное устройство — в `ARCHITECTURE.md`.

## Структура проекта

| Файл | Назначение |
|---|---|
| `src/template.html` | Каркас: `<head>` + разметка `<body>`, плейсхолдеры `{{STYLES}}` и `{{SCRIPT}}`. |
| `src/styles.css` | Все стили целиком. |
| `src/js/*.js` | Логика по модулям (`00-core` … `09-settings`), конкатенируются в порядке имён. |
| `build.mjs` | Сборка: `node build.mjs` (или `npm run build`) → один `password-guide.html`. |
| `password-guide.html` | **Собранный артефакт** — его хэширует и деплоит CI. Правится только через `src/` + сборку. |
| `index.html` | Редирект на `password-guide.html` (для GitHub Pages). Не содержит логики. |
| `README.md` | Описание, инструкция, блок «Версия и проверка» (хэш обновляет CI). |
| `.github/workflows/deploy.yml` | CI: сборка+проверка → хэш → README → релиз `v1.0.N` → `gh-pages`. |
| `tests/` | Юнит-тесты (Node `node --test`). |
| `ARCHITECTURE.md` | Устройство кода, модель данных, криптография. |

## Железные правила

1. **Один файл, ноль зависимостей.** Исходники живут в `src/` и собираются `npm run build` (`node build.mjs`) в один самодостаточный `password-guide.html` без внешних библиотек и CDN. **Правь `src/`, затем пересобирай и коммить собранный файл.** Модули `src/js/*.js` — обычный ES5 в общей области видимости, конкатенируются в порядке имён. Сетевые запросы — только необязательные и без данных пользователя: `fetch` исходника для хэша/скачивания копии и кнопка «Проверить обновления» (GitHub API). Приложение должно работать двойным кликом по файлу (`file://`) и офлайн.
2. **Не ломать формат бэкапа.** Зашифрованный блоб: `{app:'password-vault', version:1, kdf:'PBKDF2-SHA256', kdfVersion, iterations, salt, iv, ct, savedAt?}` (`savedAt` — служебная метка времени сохранения файла, без секретов). Валидация — `validBlob()`. Менять формат только с миграцией и повышением `version`.
3. **Криптографию не ослаблять.** PBKDF2-SHA256, 1 200 000 итераций (`KDF_ITERATIONS`), AES-256-GCM, `kdfVersion:2` в блобе. Старые блобы (600k, v1) обязаны оставаться читаемыми — итерации берутся из `blob.iterations`. Мастер-пароль нигде не хранится; ключ выводится на клиенте. **Seed-фраза** (`src/js/07-seed.js`, `08-seed-ui.js`): второй ключ — `ekSeed = AES-GCM(VK, ключ от фразы)`, KDF фразы — `SEED_SALT` + `SEED_KDF_ITERATIONS` (600k, фиксировано, не `blob.iterations`). Seed по умолчанию **выключен**; включение/отключение — только с подтверждением мастер-пароля; фраза показывается один раз (`seedPending` не хранится после настройки); смена пароля и укрепление KDF **не должны** ломать `ekSeed` (переоборачивается только `ekPass`). Не выводи фразу в логи/консоль.
4. **Любое изменение или удаление аккаунта — только через подтверждение мастер-паролем.** Используй существующий поток `requestAuth('edit'|'delete', id)` → `modal-auth` → `confirmAuth()`. Не добавляй «дыр», где редактирование/удаление доступно без пароля. Создание нового аккаунта остаётся свободным.
5. **Все изменения данных — через `scheduleSave()`** (автосохранение с задержкой 250 мс, перешифровка всего хранилища). Не забывай вызывать его после мутаций `state.vault`.
6. **localStorage:** реестр хранилищ — `pvg.vaults.v1` (`LS_VAULTS`), устаревший одиночный ключ — `pvg.blob.v1` (`LS_KEY`, только для миграции `migrateLegacy()`). Не удаляй миграцию: у пользователей есть старые одиночные хранилища.
7. **Безопасность данных:** никогда не логируй и не выводи мастер-пароли и открытые пароли в консоль/UI-подсказки. Хэш в «О приложении» считается от сырого исходника, а не от DOM с данными.
8. **Стиль — как в файле:** ES5-подобный JS (`var`, `function`-декларации, без стрелок/классов/modules), без сборки. Добавляя код, следуй этому стилю. Идентификаторы функций и элементов — на английском, тексты интерфейса — на русском.
9. **Веб-версия:** GitHub Pages отдаёт ветку `gh-pages`, которую пересобирает CI при пуше в `main`. Не деплой вручную. Правки → `src/` → `npm run build` → `git commit` + `git push origin main` → CI сам соберёт, проверит (`git diff --exit-code`), прогонит тесты, вшьёт версию `v1.0.<run_number>` в сборку, обновит README-хэш, релиз и `gh-pages`. Если не пересобрать локально, CI упадёт на проверке «build is up to date».
10. **Сериализационная стабильность — не ломать.** Хэш в «О приложении» для локальных (file://) копий считается по `APP_SOURCE` — сериализации DOM, захваченной в `boot()` ДО любых мутаций. Чтобы этот хэш совпадал с опубликованным, сериализация DOM должна быть **байт-в-байт равна файлу**. Поэтому в `src/template.html` запрещено: пробелы/переносы между `<html>` и `<head>` (парсер отбрасывает), между `</body>` и `</html>` (парсер переносит в `<body>`), хвостовой пробел после `</html>`, минимизированные булевы атрибуты (пиши `checked=""`, не `checked`), одинарные кавычки у атрибутов (только двойные; внутри значения атрибута — можно), сырые `&` вне сущностей (`&amp;`, `&lt;`, `&gt;`, `&quot;`, `&nbsp;`), угловые скобки `<`/`>` **в значениях атрибутов** (часть браузеров сериализует их как `&lt;`/`&gt;`, часть нет → хэш разойдётся; data-URI кодируй percent-экранированием `%3C`/`%3E`). Нарушение ловит линт в `build.mjs` и останавливает сборку — не отключай его и не «чини» шаблон в обход.
11. **Seed не даёт обход мастер-пароля.** `doSeedRecover` — единственный путь входа по фразе, и он **всегда задаёт новый мастер-пароль** и переоборачивает `ekPass`; фраза не открывает приложение «как есть». Ссылка «Забыли пароль?» (`#unlock-seed-link`) видна только если у выбранного хранилища есть `blob.ekSeed`. После `doSeedRemove` в блобе не должно оставаться `ekSeed`/`ekSeedIv`. Копирование фразы — только кнопкой `copySeedPhrase()` (подтверждение + `copyText({secret:true})` с автоочисткой буфера через 30 с), не выводи фразу в логи/консоль.
12. **Коммиты без футеров соавторства.** В сообщения коммитов **не добавлять** никакие подписи и футеры — ни «Co-Authored-By», ни «Generated with …», ни упоминания ИИ-инструментов (в т.ч. Codebuff). Сообщение коммита — только суть изменений.
13. **CSP не ослаблять.** В `<head>` стоит meta `Content-Security-Policy`: `default-src 'none'`, inline script/style (`'unsafe-inline'`), `connect-src 'self' https://api.github.com`, `img-src data:`, `object-src 'none'`. Не добавляй внешние script-хосты/CDN — это защита от подгрузки чужого кода; при новом сетевом запросе расширяй `connect-src` точечно.
14. **«⧉ Копия» (`doCloneVault`)** — независимое хранилище под новым паролем: обязательное подтверждение текущим паролем, JSON-копия данных (оригинал не мутировать), новый entry через `buildBlobWith` (v1, без seed), `markExported` для оригинала не вызывать.
15. **Настройки (`09-settings.js`)** — `state.settings` (`pvg.settings.v1` в localStorage, не в блобе): `theme` (`dark|light|system`), `idleMin` (автоблокировка, 0 = выкл), `clipSec` (очистка буфера, 0 = выкл). Тема ставится `applyTheme()` атрибутом `data-theme` на `<html>` **строго после** захвата `APP_SOURCE` в `boot()` — иначе сериализация/хэш разойдутся (в исходном шаблоне атрибута `data-theme` быть не должно). Таймаут автоблокировки и время очистки буфера читаются из настроек на каждом тике/копировании (`idleMs()`/`clipClearMs()`/`clipClearLabel()`) — без `state.settings` (тесты) работают дефолты 15 мин / 30 с.
16. **Вложенные сервисы (`parentId`)** — один уровень: контейнер всегда верхнего уровня (валидация в `saveAccount`: нельзя вложить в себя и в вложенного). На графе дети — строки с иконками внутри ноды-контейнера (`g-child`, `nodeHeightFor()`, `state.collapsedParents`), **не** отдельные ноды и **без** проводов. Маршрут восстановления — через `effectiveVia(a) = recovery.viaAccountId || parentId`: `analyzeRecovery()`/`chainFor()`/`computeRisks()` обязаны использовать `effectiveVia`, а не голый `viaAccountId` (иначе вложенные ошибочно флагуются «нет пути»). `hitTest()` проверяет строки детей до тела контейнера; клик по строке — выбор без перетаскивания. Удаление контейнера **открепляет** детей (`parentId → null`, ссылки чистятся), не удаляет. `guideVisibleIds()` добавляет предков найденных вложенных; в «Аккаунтах» дети — `.acc-card.nested` под родителем. Не забывай `scheduleSave()` после мутаций `parentId`.
17. **Вложение перетаскиванием** — `dropNestInto()` / `extractFromContainer()` / `validDropTarget()` (05-graph.js): драг ноды на контейнер вкладывает, Alt+драг (или Alt+клик) строки ребёнка вытаскивает в точку отпускания. `hitTest(wx, wy, excludeId)` при драге ноды исключает саму перетаскиваемую ноду (иначе она перекрывает цель); валидная цель — зелёная рамка (`dropTarget`), невалидная — красная + тост-причина при отпускании (`dropRejectTarget` → `dropNestInto` возвращает false с тостом). После `dropNestInto`/`extractFromContainer` вызывай `scheduleSave()` + `renderGraph()`/`renderAccounts()`/`renderGuide()`. Подсказка про жесты — в `#graph-hint`.
18. **Точки и сокеты вложенных** (05-graph.js): точка на строке ребёнка — зелёная `#4caf7d`, если свой `viaAccountId` = родитель, красная `#e05a5a`, если наружу; нет своего маршрута — точки нет (наследует родителя). **Вложенный Telegram** (`nestedTelegramOf(a)` — ровно один вложенный Telegram, контейнер не Telegram): на контейнере красный сокет `SOCKET_Y+16` (`childVia`, исходная почта) и зелёный `SOCKET_Y+32` (`childNotify`, уведомления); провода от контейнера рисуются только если цель **наружу** (на родителя — дефолт, провода нет, зелёная точка). Перетаскивание сокетов → `setVia(childId,…)`/`setNotify(childId,…)` (на родителя можно вернуть), `Del` разрывает (`data-src` = id Telegram). Добавляя сокеты/провода/точки, не забудь `nodesSvg()`/`wiresSvg()`/`hitTest()` и легенду в `#graph-hint`-блоке.

- Запуск: `npm test` (или `node --test`). CI запускает тесты перед деплоем — падение блокирует публикацию.
- Добавляя чистую логику (крипто, валидация, миграция, индикаторы), добавляй тест в `tests/`.

## Как проверять изменения

Ручная проверка в браузере (превью), минимум:

1. Создание хранилища → вход по мастер-паролю → блокировка → повторный вход.
2. Добавление аккаунта (с данными восстановления и общим доступом) → автосохранение.
3. «Путеводитель»: маршрут, подсветка на графе, «Проверка безопасности», дубли паролей.
4. Поиск по аккаунтам.
5. Экспорт → импорт в другом окне/браузере (данные открываются по мастер-паролю, ничего не перезаписывается).
6. Изменение/удаление аккаунта: неверный пароль отклоняется, верный — проходит.
7. «О приложении»: хэш совпадает с SHA-256 файла; на веб-версии версия из `VERSION`.
8. Режим стрима: «🙈 Скрыть данные» — названия узлов → сервисные подписи, почты → звёздочки, панель скрыта, редактирование заблокировано; повторный клик возвращает всё.
9. Консоль без ошибок и без CSP-нарушений.
10. Копирование пароля: тост «буфер очистится через N с/мин» (по настройке, по умолчанию 30 с); через N с буфер очищен (или не тронут, если там уже другое); при «Не очищать» буфер не трогается, а подпись/confirm говорят «очистка буфера выключена».
11. Настройки «⚙»: смена темы (тёмная/светлая/системная) применяется сразу и переживает перезагрузку; автоблокировка: открытое хранилище блокируется через настроенное время бездействия, при «Выключена» — не блокируется; время очистки буфера влияет на тост и фактическую очистку.
12. Категории тулбара: клик по категории открывает выпадающее меню, клик по пункту выполняет действие и закрывает, клик мимо — закрывает; действия из меню работают как раньше (в т.ч. `#btn-stream`/`#btn-strengthen` обновляются внутри меню).
13. Seed-фраза: включение (показ 12 слов → проверка → активна), блокировка → ссылка на экране входа → восстановление по фразе с новым паролем, смена пароля/укрепление не ломают фразу, отключение по мастер-паролю → фраза перестаёт открывать. Для хранилища без seed на экране входа видно предупреждение «восстановление по seed не настроено», а ссылки «Забыли пароль?» нет; при переключении на хранилище с seed — наоборот. Это же предупреждение показывается в панели «Путеводитель» внутри приложения и должно скрываться сразу после включения seed и появляться после отключения.
14. Вложенные сервисы: создай почту-контейнер → вложи в неё 2–3 сервиса (селект «Внутри аккаунта» или **драгом**) → на графе сервисы строками с иконками внутри ноды (не отдельные ноды); клик по строке выбирает сервис, маршрут начинается с родителя, родитель подсвечен; шеврон сворачивает/разворачивает; в «Аккаунтах» дети — карточки под родителем с бейджем «N вложено»; поиск по имени ребёнка показывает его и контейнер; удаление контейнера открепляет детей (тост в подтверждении); вложение в вложенного и в себя отклоняется тостом. **Перетаскивание:** перетащи ноду на контейнер — подсветка зелёным и вложение по отпусканию; перетащи контейнер с детьми на другую ноду — красная подсветка и тост «нельзя вложить контейнер»; Alt+перетаскивание (или Alt+клик) строки вложенного сервиса — «призрак» за курсором и извлечение в точку отпускания. **Точки:** у вложенного со своим маршрутом на родителя — зелёная точка, наружу — красная (есть в легенде). **Вложенный Telegram:** на контейнере ниже синего красный сокет (исходная почта) и зелёный (уведомления); потяни красный на входной сокет другого аккаунта — красный провод и красная точка; верни на входной сокет родителя — зелёная точка, провод исчезает; зелёный сокет тянется на «почту уведомлений».
15. «Укрепить шифрование»: у нового/уже укреплённого хранилища (`blob.iterations >= KDF_ITERATIONS`) кнопка горит зелёным «🛡 Шифрование укреплено» и заблокирована, модалка не открывается; у legacy-хранилища (600k) — активна, после укрепления переходит в done-состояние.
16. «⧉ Копия»: создание копии, вход в неё по новому паролю, оригинал открывается старым — и наоборот; неверный текущий пароль копию не создаёт.

## Частые точки правок

- Добавить поле в аккаунт: `emptyAccount()` (стартовая схема), `openEditor()`/`readEditorForm()` (форма), `renderGuideDetail()` (шаги маршрута), `accountCard()` (список).
- Новый тип-иконка: `ACCOUNT_TYPES` + глиф-функция рядом с `envGlyph()`/`goGlyph()`.
- Новое правило риска: `computeRisks()`.
- Граф: `renderGraph()`, `updateChainHighlight()`, `vaultLayout()`/`ensureLayout()` (позиции узлов и камера сохраняются в `state.vault.layout`).
- Экран/модалка: HTML-блок в `<body>`, `showScreen()`/`openModal()`.
