# ARCHITECTURE.md — устройство приложения

Исходники — в `src/`, собираются `npm run build` в один самодостаточный `password-guide.html`. Ниже — как он устроен изнутри.

## Структура исходников и сборка

- `src/template.html` — каркас: `<head>` (включая CSP-meta) + разметка `<body>`; плейсхолдеры `{{STYLES}}` (внутри `<style>`) и `{{SCRIPT}}` (внутри `<script>`).
- `src/styles.css` — все стили.
- `src/js/*.js` — логика по модулям, конкатенируются в порядке имён файлов:
  - `00-core.js` — константы, `state`, утилиты, иконки, toast/copy/clipboard, showScreen/модалки.
  - `01-crypto.js` — PBKDF2/AES-GCM, блоб, реестр хранилищ, индикатор бэкапа.
  - `02-auth.js` — создание/вход/блокировка/смена пароля, операции над аккаунтами.
  - `03-accounts.js` — вкладки панели, список аккаунтов, редактор.
  - `04-guide.js` — анализ восстановления, риски, «Путеводитель».
  - `05-graph.js` — нодовый редактор, рендер, взаимодействия, режим стрима.
  - `06-tools.js` — экспорт/импорт, «О приложении», генератор, автоблокировка, запуск.
  - `09-settings.js` — настройки: тема, таймаут автоблокировки, очистка буфера (localStorage `pvg.settings.v1`).
- `build.mjs` — склеивает всё в `password-guide.html` (`'use strict';` добавляется сборщиком первой строкой скрипта). Модули — ES5 в общей области видимости (как и был монолит): порядок конкатенации сохраняет порядок исполняемых строк; `var`/`function` хойстятся.
- Собранный `password-guide.html` **коммитится**; CI пересобирает и сверяет (`git diff --exit-code`), поэтому исходники и артефакт не могут разойтись.

## Общая схема

```
boot()
 └─ migrateLegacy()  — одноразовый перенос старого одиночного хранилища
 └─ экран: setup (нет хранилищ) | unlock (есть хранилища)
      └─ tryUnlock() — PBKDF2 из пароля → AES-GCM расшифровка блоба → state.vault
           └─ экран main: вкладки «Аккаунты» / «Путеводитель»
                └─ правки → scheduleSave() → saveBlob() (перешифровка → localStorage)
                └─ lock() — сохранение + сброс ключа из памяти
```

## Криптография и хранение

- `deriveKey(pass, salt, iterations)` — PBKDF2-SHA256 → AES-GCM `CryptoKey`. Параметры хранятся в блобе.
- `encryptWithKey(vault, key)` / `decryptWithKey(blob, key)` — AES-256-GCM, случайный IV на каждый блоб.
- `buildBlob(vault)` → `{app:'password-vault', version:1|2, kdf:'PBKDF2-SHA256', kdfVersion:2, iterations:1200000, salt, iv, ct, savedAt?}`. `buildBlobWith(vault, key, salt, iterations)` — независимая сборка блоба под заданным ключом (всегда v1, без seed), для «копии хранилища». В блобе **нет открытых данных** (кроме служебной метки `savedAt` — времени сохранения файла, без секретов). Старые блобы v1 (600k, без `kdfVersion`) остаются читаемыми: разблокировка берёт итерации из `blob.iterations`.
- **Формат v2 (seed-фраза).** Данные шифруются стабильным ключом `VK` (AES-GCM, 256 бит); `VK` обёрнут производным ключом от пароля — `ekPass` (`{ekIv, ekPass}` в блобе) — и, если seed включён, ключом от seed-фразы — `ekSeed` (`{ekSeedIv, ekSeed, seedIterations}`). Смена пароля и укрепление KDF пере-оборачивают только `ekPass` (`buildBlob` экспортирует `VK` и шифрует его текущим `state.derivedKey`); `ekSeed` не трогается, поэтому фраза работает всегда, пока не отключена. Хранилища без seed остаются в формате v1 (миграция v1→v2 происходит только при включении seed — в `doSeedSetupConfirm`). Разблокировка (`tryUnlock`) по наличию `blob.ekPass` выбирает путь: unwrap `ekPass` → `VK` → расшифровка. **Формат выводится из данных, а не из глобального флага**: `vaultIsV2()` = `blob.ekPass || seedWrap.ct` (глобальный флаг-«воспоминание» рассинхронизировался между сессиями и ронял `exportKey` на не-extractable ключе); `doSetup` сбрасывает остатки seed-состояния.
- `validBlob(b)` — проверка структуры перед импортом/миграцией (v2-блобы проходят: поля v1 + дополнительные).
- localStorage: `pvg.vaults.v1` — массив `{id, name, blob, updatedAt, lastExportAt, fileName}` (реестр нескольких хранилищ; `fileName` — имя последнего экспортированного/импортированного файла); `pvg.blob.v1` — устаревший одиночный формат, читается только `migrateLegacy()`.
- `scheduleSave()` — отложенное на 250 мс автосохранение (`saveBlob()`); статус «Сохранено ✓» выводится в плашку `#save-status` в нижнем правом углу поля графа.
- Смена пароля `doChangePass()`: проверить текущий пароль расшифровкой → вывести новый ключ → перешить `ekPass` (для v2 `state.key`/`VK` не меняется, `buildBlob` переоборачивает).
- Укрепление KDF `doStrengthenKdf()`: пароль тот же, но ключ пере-выводится с 1.2M итераций и свежей солью (перешифровка без смены пароля; для v2 — снова только `ekPass`). Кнопка «🛡 Укрепить шифрование» (`#btn-strengthen`): `updateStrengthenButton()`/`isStrengthened()` (по `blob.iterations >= KDF_ITERATIONS`) переводят её в состояние «🛡 Шифрование укреплено» (класс `done`, зелёный, `disabled`) — повторное укрепление недоступно, `openStrengthenKdf()` на укреплённом хранилище показывает тост и не открывает модалку. Обновляется в `enterMain()` и после `doChangePass()`/`doStrengthenKdf()`.
- **Seed-фраза (`07-seed.js`, `08-seed-ui.js`).** BIP-39, 12 слов (128 бит энтропии + контрольная сумма), словарь 2048 слов встроен (`SEED_WORDS_STR`). `generateSeedPhrase()` / `seedPhraseValid()` (валидация и слов, и контрольной суммы) / `deriveSeedKey(phrase)` — PBKDF2 с фиксированной солью `SEED_SALT` и `SEED_KDF_ITERATIONS` (600k, не зависит от `blob.iterations`). Настройка (`openSeedModal`): подтверждение мастер-паролем реальной расшифровкой → генерация → показ фразы **один раз** → проверка 3 случайных слов → запись `ekSeed` и `state.vault.seedEnabled = true`. Кнопка «📋 Скопировать фразу» (`copySeedPhrase()`): подтверждение `confirm()` + `copyText({secret:true})` — буфер очищается через настроенное время (общий механизм `scheduleClipboardClear`, подпись `clipClearLabel()`). Поля проверки и их подписи «Слово №N» строятся из **отсортированного** списка индексов (`ask`) — в том же порядке, что и сравнение в `doSeedSetupConfirm`; иначе подпись не соответствовала бы проверяемому слову (баг порядка `pool` vs `ask`). Отключение (`doSeedRemove`) — только с мастер-паролем, удаляет `ekSeed`. Восстановление (`doSeedRecover`, с экрана входа, по ссылке `#unlock-seed-link`, видимой только если у выбранного хранилища есть `blob.ekSeed`): фраза → `seedPhraseValid` → `deriveSeedKey` → unwrap `ekSeed` → `VK` → расшифровка → новый соль + новый производный ключ → `saveBlob()` (seed сохраняется). `updateSeedUnlockLink()` (из `renderVaultList()`) переключает оба элемента экрана входа: ссылку восстановления (видна при `ekSeed`) и предупреждение `#unlock-seed-warn` «восстановление по seed не настроено» (видно при выбранном хранилище без seed) — чтобы о риске потери данных напоминало заранее. Такое же предупреждение `#guide-seed-warn` показывается внутри приложения в панели «Путеводитель» (`updateGuideSeedWarn()` из `renderGuide()`, по `state.seedWrap`), обновляется при включении/отключении seed (`doSeedSetupConfirm`/`doSeedRemove`). `unlockWithKey(blob, key)` — общий путь разблокировки (unwrap `ekPass` для v2, прямая расшифровка для v1).

## Модель данных (в `state.vault`, расшифрована в памяти)

```
vault: {
  version: 1,
  accounts: [ Account ],
  layout: { nodes: { [id]: {x,y} }, camera: {x,y,s} }   // раскладка графа
}

Account: {
  id, type, name, username, password, notes,
  parentId,                                 // вложенный сервис: живёт внутри аккаунта-контейнера
  recovery: { viaAccountId, codes, phone, notes, questions: [{q,a}] },
  notifyEmailId,                            // Telegram: почта для уведомлений (зелёный выход)
  shared: [ {name, username, password} ]                  // «кто ещё может входить»
}
```

- `type` — ключ из `ACCOUNT_TYPES` (иконки, инлайн-SVG, без сети).
- `viaAccountId` — связь «этот аккаунт восстанавливается через…»; из неё строится граф и маршруты.
- `notifyEmailId` — (только Telegram) связь «почта для уведомлений»; в маршрутах восстановления не участвует.
- `parentId` — **вложенный сервис**: один уровень вложенности, контейнер всегда верхнего уровня. Хелперы: `containerChildren(a)` (порядок из массива), `descendantIds(id)` (транзитивно), `effectiveVia(a)` = `recovery.viaAccountId || parentId` — вложенный без своего маршрута **наследует родителя**. `effectiveVia` участвует в `analyzeRecovery()`/`chainFor()`/`computeRisks()`; у вложенного без своего маршрута риск «нет пути» не срабатывает. Валидация при сохранении: нельзя вложить в самого себя и в вложенного (контейнер — только верхний уровень).
- Раскладка графа сохраняется **внутри хранилища** (`vault.layout`) — переносится с бэкапом.

## Экраны и модалки

- `screen-setup` — создание хранилища; `showSetupScreen('first'|'additional')`.
- `screen-unlock` — список хранилищ, вход по мастер-паролю, импорт, скачивание копии, «О приложении».
- Индикатор режима: `renderModeBadge()` (вызывается из `boot()`) заполняет плашки `.mode-badge` на обоих экранах входа — «🌐 Онлайн-версия» при `http(s)` или «💻 Локальная версия (offline)» при `file://`. Заодно он скрывает в `file://` элементы `.dl-copy-btn`/`.dl-copy-hint` («Скачать локальную копию» и подсказку в «О приложении»): в локальной версии это и есть тот самый файл, качать его самого бессмысленно.
- `screen-main` — полноэкранный (`100vw`×`100vh`, без шапки и футера) единый экран: `.workspace` (`2fr 1fr`) — слева граф, справа `.side-panel` с внутренними вкладками `Аккаунты` / `Путеводитель` (`switchPanel()`). Тулбар графа сгруппирован в **выпадающие категории** `.graph-menu` (открытие — `toggleGraphMenu()`, клик по пункту или мимо закрывает через `closeGraphMenus()`): «🗄 Хранилище» (экспорт/импорт/копия), «🛡 Защита» (сменить пароль/укрепить/seed), «🧩 Узлы» (аккаунт/изменить/удалить), «👁 Вид» (зум/вписать/режим стрима); снаружи остались частые действия «⚙ Генератор», «🔒 Заблокировать», «⚙ Настройки», «ℹ️ О приложении». Кнопки `#btn-strengthen`/`#btn-stream` живут внутри категорий, но по-прежнему обновляются по id (`updateStrengthenButton()`/`toggleStreamMode()`). Тулбар тонкий (padding 5px); подсказка по управлению графом вынесена из тулбара текстовой плашкой `#graph-hint` в нижний левый угол поля нод (absolute в `.graph-stage`, рядом с `#corner-status` справа); название приложения — плашка `.graph-title` в верхнем левом углу канваса (при выборе узла под заголовком `updateGraphTitleNotes()` показывает заметки аккаунта — `a.notes` и `recovery.notes`), статус сохранения — `#save-status` в нижнем правом. Колонки складываются в одну только уже 560px.
- **Индикатор бэкапа**: плашка `#backup-status` над `#save-status` (правый нижний угол канваса). `backupInfo()`/`refreshBackupStatus()` сравнивают `entry.updatedAt` и `entry.lastExportAt` **по календарным дням** (`dayOf()`, обнуление времени суток): «Бэкап актуален», если последняя правка и экспорт случились в один день, а не секунда в секунду. `markExported(fileName)` (из `exportFile()`/`exportClipboard()`) фиксирует время экспорта, сохраняет имя файла и перезаписывает реестр. Флаг `state.dirty` поднимается в `scheduleSave()` и сбрасывается в `saveBlob()`, а `updatedAt` двигается только при `dirty` — чтобы блокировка (пересохранение без правок) не помечала бэкап устаревшим. Клик по плашке открывает экспорт.
- Модалки: `modal-editor` (аккаунт), `modal-auth` (подтверждение мастер-паролем), `modal-export`, `modal-import`, `modal-change-pass`, `modal-strengthen`, `modal-generator`, `modal-about`, `modal-seed` (настройка/отключение seed-фразы), `modal-seed-recover` (восстановление доступа по фразе), `modal-clone` (копия хранилища), `modal-settings` (настройки «⚙»). Закрытие — только осознанное: `initModalCloseButtons()` (вызывается в `boot()` после захвата `APP_SOURCE`) инжектит в каждую `.modal-panel` кнопку «✕» (для `modal-auth` — через `closeAuthModal()`, остальные — `closeModal(id)`); клик по фону окно НЕ закрывает.

## Ключевые потоки

- **Защита правок/удаления:** `requestAccountEdit(id)` / `requestDeleteAccount(id)` → `requestAuth(action, id)` → `modal-auth` → `confirmAuth()` сверяет пароль реальной расшифровкой текущего блоба → только потом `openEditor()` / удаление. Единая точка входа — без обхода.
- **Импорт** `applyImport(fileName)` — валидация `validBlob()`, добавляет хранилище в реестр (не перезаписывает), сохраняет имя файла и метку `savedAt` из блоба, блокируется и просит пароль нового хранилища. Тост показывает «когда сохранён и в какой версии»; карточка хранилища на экране входа — «файл: <имя> · сохранён: <дата> · формат v1.x».
- **Экспорт** `exportFile()` — скачивание `.json` с именем `exportFileName()` (у импортированных хранилищ сохраняется **оригинальное имя файла**, у остальных — `rearcovery-backup-<дата>.json`); `exportClipboard()` — в буфер.
- **Копия хранилища** `doCloneVault()` (кнопка «⧉ Копия», `modal-clone`): подтверждение текущим мастер-паролем (`unlockWithKey`) → JSON-клон `state.vault` → новая соль + `deriveKey(новый пароль)` → `buildBlobWith` (v1, без seed) → новый entry в реестре + автоскачивание `.json` (`rearcovery-copy-<дата>.json`). Оригинал не мутируется; `markExported` для оригинала не вызывается.
- **Поиск** `filterAccounts()` — по названию, логину, заметкам, телефону, общему доступу; `state.search`; сброс при блокировке.
- **Дубли паролей** `dupPasswordGroups()` — группа по одинаковому `password`; бейдж «⚠️ дубль пароля» на карточке + риск в «Проверке безопасности».
- **Генератор** `generatePassword()` — `crypto.getRandomValues` + Fisher–Yates, чтобы обязательные классы символов не скапливались в начале.
- **«О приложении»** `openAbout()` — `APP_VERSION` (версия вшита в файл при сборке; на http(s) дополнительно подстраховка из `./VERSION`); хэш: на http(s) = SHA-256 отданного файла (`fetch(location.href)`), на `file://` = SHA-256 копии `APP_SOURCE`, сохранённой при загрузке ДО мутаций DOM. Благодаря сериализационно-стабильной сборке `APP_SOURCE` байт-в-байт равен файлу, поэтому хэш локальной копии совпадает с опубликованным. Хэш кешируется в `ABOUT_HASH`. На `file://` после расчёта хэша **автоматически** запускается `checkUpdates()` — сверка с последним релизом не требует нажатия кнопки (важно: «Сохранить страницу как» в браузере меняет байты файла, и хэш перестаёт совпадать, хотя код тот же).
- **Проверка обновлений** `checkUpdates()` — единственный внешний запрос в коде: `fetch` к GitHub API (`/repos/{GITHUB_REPO}/releases/latest`); сверяет SHA-256 последнего релиза (из тела релиза) с `ABOUT_HASH` текущего файла. Данных пользователя не передаёт.
- **Скачивание копии** `downloadLocalCopy()` — на http(s) `fetch` исходника; на `file://` — `APP_SOURCE`.
- **Автоблокировка** — таймаут из настроек (`idleMs()` = `state.settings.idleMin`; по умолчанию 15 мин, 0 = выключена), перечитывается на каждом тике `startIdleWatch()` (10 с), поэтому смена настройки применяется сразу. `lock()` сначала сохраняет изменения.
- **Тема** — `html[data-theme="dark"]`/`["light"]` (и `data-color-scheme`) ставится `applyTheme()` из настроек (`theme: dark|light|system`; `system` следует за `prefers-color-scheme` через `initThemeListener()`). Атрибут на `<html>` — **только динамически** (после захвата `APP_SOURCE` в `boot()`), чтобы сериализация/хэш файла не менялись; светлая тема = CSS-переменные `:root`, тёмная — переопределения `html[data-theme="dark"]` (экраны входа, модалки; рабочее поле графа тёмное всегда, Send Nodes-стиль).
- **CSP** — meta `Content-Security-Policy` в `<head>`: `default-src 'none'`; inline script/style (`'unsafe-inline'`); `connect-src 'self' https://api.github.com` (хэш/скачивание копии/VERSION/проверка обновлений); `img-src data:` (favicon); `object-src 'none'`; `base-uri 'none'`; `form-action 'none'`. Внешние script-хосты запрещены.
- **Буфер обмена** — `copyText(t, {secret:true})` (пароль в карточке и в шагах маршрута) планирует `scheduleClipboardClear()`; через `clipClearMs()` мс (из настроек `state.settings.clipSec`, по умолчанию 30 с, 0 = выключена) `clearClipboardIfSecret()` читает буфер и стирает секрет, только если он всё ещё там (read-сравнение), а при недоступном `readText` очищает безусловно. Тост: «Скопировано · <clipClearLabel()>» (подпись следует за настройкой: «буфер очистится через N с/мин» или «очистка буфера выключена»); та же подпись — в подсказке и `confirm()` копирования seed-фразы.

## Путеводитель и граф

- Единый экран: `.workspace` — две колонки `2fr 1fr` (граф / панель), тёмная тема `#workspace` (Send Nodes-стиль). Панель `.side-panel`: вкладки `Аккаунты` (`#panel-accounts`, список карточек) и `Путеводитель` (`#panel-guide`: выбор аккаунта, поиск `#guide-search`, «Проверка безопасности», «Описание и маршрут»). Боковое расположение держится до `560px` (панель не уже `280px`), только на очень узких экранах колонки складываются в одну.
- Синхронизация выбора: клик по узлу графа подсвечивает карточку в списке (`selectNode()` → `highlightAccountCard()`); клик по карточке `#accounts-list` (делегированный слушатель `initAccountsList()`) выбирает узел и переключает панель на «Путеводитель» (`selectFromList()`).
- Поиск в путеводителе: `guideFilteredAccounts()` — по названию, логину, обоим полям заметок (`a.notes` и `r.notes`), телефону, кодам, вопросам, общему доступу; `guideVisibleIds()` — множество найденных id. Активный запрос фильтрует и граф (`wiresSvg()`/`nodesSvg()`/`hitTest()`/`fitView()` учитывают видимость), и список выбора, и «Проверку безопасности». Тот же набор полей ищет `filterAccounts()` во вкладке «Аккаунты».
- `analyzeRecovery()` — DFS: поиск циклов (`inCycle`), глубина цепочки (`depthOf`).
- `chainFor(id)` — маршрут восстановления по `viaAccountId` до конечной точки (или цикл).
- `computeRisks()` — «нет пути и данных», «цикл», «короткий пароль», «дубль пароля». Вложенный сервис без своего маршрута не флагуется: путь даёт родитель (`effectiveVia`).
- **Вложенные сервисы** (`parentId`): на графе дети рендерятся **строками с иконками внутри ноды-контейнера** (`g-child`, `nodeHeightFor()` растёт под список; шеврон в шапке `toggleContainerCollapse()` — свёрнутый контейнер = одна строка «N вложено — развернуть», `state.collapsedParents` в памяти), а не отдельными нодами — проводов у детей нет. Раскладка (`ensureLayout()`) учитывает только верхний уровень и ставит новые ноды ниже уже стоящих (высокие контейнеры не наезжают). `hitTest()` проверяет строки детей раньше тела контейнера; клик по строке выбирает ребёнка (перетаскивания нет — нет позиции). Подсветка маршрута: `updateChainHighlight()` красит и строки детей (`.g-child`). Удаление контейнера **открепляет** детей (`deleteAccountNow`: `parentId → null`, ссылки `viaAccountId`/`notifyEmailId` чистятся), не удаляет. Поиск: `guideVisibleIds()` добавляет предков найденных вложенных; во вкладке «Аккаунты» дети — карточки `.acc-card.nested` под родителем (бейдж «N вложено»), при поиске показываются только совпавшие. В редакторе — селект «Внутри аккаунта» (`ed-parent`).
- Нодовый редактор (стиль Blender): SVG-канвас с сеткой; узлы перетаскиваются, связи создаются перетаскиванием за сокеты; зум колесом/кнопками; панорама; выбор узла подсвечивает маршрут (`updateChainHighlight()` — обновляет атрибуты существующих элементов, CSS-транзишены ~0.45 с); `Del` удаляет выбранное; двойной клик — редактирование (через `requestAccountEdit`, т.е. с подтверждением пароля).
- **Вложение перетаскиванием:** перетащить ноду на контейнер → `dropNestInto()` (`parentId`, валидность — `validDropTarget()`: не в себя, не в вложенного, не контейнер с детьми); валидная цель подсвечивается зелёной рамкой, невалидная — красной + тост-причина при отпускании (`dropRejectTarget`). **Извлечение:** Alt+перетаскивание (или Alt+клик) строки вложенного сервиса — `extractFromContainer()` возвращает его на верхний уровень в точку отпускания (за курсором летит «призрак» `extractGhostSvg()`). `hitTest(wx, wy, excludeId)` исключает перетаскиваемую ноду — иначе она перекрывает цель под курсором.
- Раскладка слева направо: восстанавливаемые слева, конечные точки справа (`ensureLayout()`).
- Шапка узла — в цвет сервиса (`nodeHeaderColor()`: фирменные цвета Google/Telegram, градиент Instagram, остальные — из `ACCOUNT_TYPES.tile`); красная `#d64545` — нет ни пути, ни данных восстановления (независимо от сервиса); оранжевая `#e0913b` — участник цикла.
- Узел Telegram имеет **два выходных сокета**: красный — исходная почта (это `recovery.viaAccountId`, перекрашен), зелёный — почта для уведомлений (`notifyEmailId`). Провода: красный `garr-red`/`#e05a5a`, зелёный `garr-green`/`#4caf7d`; ключ зелёного провода `a.id~dstId`, у красного — `a.id>dstId`, выбор провода хранит `wireKind` ('via'|'notify'), чтобы `Del` разрывал нужную связь (`setVia()`/`setNotify()`). В редакторе для типа Telegram появляется селект «Почта для уведомлений» (`ed-notify`, `syncNotifyField()`), а лейбл поля восстановления меняется на «Исходная почта (восстановление Telegram)». Карточка аккаунта и шаги маршрута показывают «уведомления → …».
- Если у аккаунта нет пароля, он помечается **«пароль не записан»** (красным) в трёх местах: строка в теле узла (`pwRow`, высота ноды 86px), значение «Пароль» в карточке списка и в шаге маршрута.
- **Режим стрима** (`state.streamMode`, кнопка `#btn-stream` → `toggleStreamMode()`): названия узлов и тултипы маскируются (`streamName()`/`streamLabel()` — сервисная подпись из `ACCOUNT_TYPES`, почты mail/google/mailru/proton — «•••••»), строки логинов скрываются, плашка заметок `updateGraphTitleNotes()` очищается, правая панель полностью скрывается за `#stream-overlay` (класс `.side-panel.streaming`), редактирование/удаление блокируется тостом. Режим не сохраняется в хранилище.

## Тесты

- `tests/` — юнит-тесты (Node `node --test`, без браузера): `crypto.test.mjs` (крипто-путь), `backup.test.mjs` (индикатор бэкапа), `clipboard.test.mjs` (очистка буфера), `settings.test.mjs` (настройки: тема, автоблокировка, буфер), `nesting.test.mjs` (вложенные сервисы: `effectiveVia`, `containerChildren`/`descendantIds`, `nodeHeightFor`, цепочка через родителя, цикл через вложенность, открепление при удалении, запрет вложения в вложенного, поиск и карточки). Харнесс `loadApp()` в `tests/helpers.mjs` извлекает `<script>` из `password-guide.html` и гоняет его в `vm`-контексте с фейковыми `document`/`localStorage`/`navigator`, таймеры заглушены.
- Покрыто: round-trip `encryptWithKey`/`decryptWithKey` (юникод, tamper-детект, чужой ключ), полный `buildBlob` с 1.2M итерациями, `kdfVersion` и `savedAt`, совместимость старого блоба v1 (600k), re-KDF 600k → 1.2M через `doStrengthenKdf`, `validBlob`, `migrateLegacy` (перенос/битые данные), `applyImport` (битый JSON, не-блоб, битый шифртекст, имя файла и `savedAt` в реестре), `backupInfo`/`refreshBackupStatus`/`markExported` с дневной гранулярностью («день в день» — актуален) и `exportFileName`, dirty-логика `saveBlob`, очистка буфера после копирования пароля (обычная, «не затирать чужое», fallback при недоступном readText).
- Запуск: `npm test`. CI выполняет `node --test` до хэша/сборки/релиза.

## Деплой и проверяемость

- CI `.github/workflows/deploy.yml` на push в `main`: сборка+проверка синхрона (`git diff --exit-code`) → `node --test` → **инъекция версии** (`PVG_VERSION=v1.0.<run_number>` пересборка — версия попадает и в локальные копии, и в опубликованный хэш) → `sha256sum password-guide.html` → обновление строки «Хэш текущей версии» в README (коммит обратно) → сборка ветки `gh-pages` (сайт: `password-guide.html`, `index.html`, `README.md`, `VERSION` = `v1.0.<run_number>`) → релиз GitHub `v1.0.N` с хэшем в описании.
- GitHub Pages: источник — ветка `gh-pages` (зарелиженная версия, не live-main). Пуш в `gh-pages` триггерит сборку; смена источника через API сборку не запускает.
- Проверка пользователем: «О приложении» → SHA-256 на экране == хэш в релизе/README. Для локальной (file://) копии это работает потому, что сборка сериализационно-стабильна: `build.mjs` на этапе сборки линтит шаблон (запрещены: пробелы между `<html>`/`<head>` и `</body>`/`</html>`, хвостовые пробелы после `</html>`, минимизированные булевы атрибуты — только `checked=""`, одинарные кавычки атрибутов — только двойные, сырые `&` вне сущностей, угловые скобки `<`/`>` в значениях атрибутов — data-URI кодируются `%3C`/`%3E`) и при нарушении останавливает сборку. Угловые скобки в атрибутах — реальный кейс расхождения: Firefox и часть сборок Chromium сериализуют их как `&lt;`/`&gt;` (+24 байта для favicon-`data:image/svg+xml`), Chrome — нет. `boot()` захватывает `APP_SOURCE` до `renderModeBadge()` и любых других мутаций DOM (включая `loadSettings()`/`applyTheme()`, которые меняют атрибуты `<html>`).
