# 🔐 Путеводитель по паролям

Один самодостаточный HTML-файл: зашифрованный сейф паролей + путеводитель по восстановлению доступа. Работает полностью офлайн, ничего не отправляет в сеть.

## Версия и проверка

- **Актуальная версия на Pages:** последний релиз (см. раздел Releases) — сайт отдаёт только зарелиженные версии.
- **Хэш текущей версии:** `878453866db6f432424e0dac639e7ad30b25737495bf7a2247997d66666c0579` *(обновляется автоматически при каждом пуше в `main`)*

**Как проверить, что перед вами официальный код:** откройте «ℹ️ О приложении» на странице, скопируйте SHA-256 и сравните с этим значением (или с хэшем в описании релиза). Совпали — код байт-в-байт тот же, что опубликован в репозитории; можно вводить мастер-пароль. Не совпали или хэша нет — закройте страницу: это не официальная копия.

**Локальная копия тоже проверяется:** версия вшивается в файл при сборке (у локальной копии она совпадает с релизной, без пометки «(локальная копия)»), а хэш считается от исходного текста файла, восстановленного до любых изменений страницы, — поэтому для скачанной локальной копии хэш совпадает с опубликованным. В локальной копии «ℹ️ О приложении» автоматически сверяет хэш с последним релизом (без нажатия кнопки). Важно: скачивайте копию кнопкой приложения, а не «Сохранить страницу как» в браузере — браузер сохраняет изменённую страницу, и хэш перестаёт совпадать, хотя код тот же.

⚠️ Это защищает от подмены по пути (форк, кэш, устаревшая копия), но не от компрометации самого аккаунта GitHub: если злоумышленник получит доступ к репозиторию, он сможет поменять и код, и хэш. Самый надёжный режим — скачать HTML один раз, проверить и пользоваться локально.

## Возможности

- **Несколько хранилищ** — у каждого свой мастер-пароль и свои данные.
- **Шифрование** — PBKDF2-SHA256 (1 200 000 итераций) → AES-256-GCM, всё на клиенте; кнопка «🛡 Укрепить шифрование» перешифровывает старые хранилища на новый порог без смены пароля.
- **Аккаунты** — логин, пароль, заметки, данные восстановления (резервные коды, телефон, контрольные вопросы), общие пароли. Слоты без пароля помечаются «пароль не записан».
- **Путеводитель** — маршруты восстановления по шагам + интерактивный нодовый редактор в стиле Blender (связи перетаскиванием, зум, панорама, подсветка маршрута). Шапки узлов — в цвет сервиса; аккаунт без резерва — красный.
- **Telegram** — два адреса: исходная почта (красный выход ноды) и почта для уведомлений (зелёный выход).
- **Проверка безопасности** — аккаунты без пути восстановления, циклы A→B→A, короткие и повторяющиеся пароли.
- **Режим стрима «🙈 Скрыть данные»** — скрывает личное для стрима: названия узлов заменяются сервисными подписями (Telegram, MEGA…), почты — звёздочками, панель с данными полностью скрывается.
- **Индикатор режима** — на экранах входа плашка «🌐 Онлайн-версия» или «💻 Локальная версия (offline)» показывает, откуда запущено приложение.
- **Индикатор бэкапа** — плашка в углу показывает «бэкап актуален / устарел / не создан» и напоминает сделать экспорт после изменений данных (клик по плашке открывает экспорт). Бэкап считается актуальным, если экспорт сделан **в день** последних изменений (а не секунда в секунду).
- **Имя файла и версия при импорте/экспорте** — при сохранении бэкапа сохраняется оригинальное имя файла, при импорте показывается, когда файл сохранён и в какой версии формата; карточка хранилища на экране входа показывает «файл · дата сохранения · формат».
- **Seed-фраза восстановления** — опциональный резервный доступ к хранилищу, если забыт мастер-пароль: 12 слов BIP-39 (показываются один раз при настройке). Включение/отключение — в тулбаре «🌱 Seed-фраза», по умолчанию выключено; отключить можно только мастер-паролем. Смена пароля и укрепление шифрования seed не ломают.
- **Копия хранилища под новым паролем** — кнопка «⧉ Копия» создаёт независимую копию всех данных с новым мастер-паролем: копия появляется в списке хранилищ и сразу скачивается файлом .json; оригинал и его пароль не меняются. Требует подтверждения текущим паролем.
- **Автоочистка буфера обмена** — через 30 секунд после копирования пароля буфер очищается; скопированное за это время другое содержимое не затирается.
- **Поиск по аккаунтам**, иконки сервисов, генератор паролей, экспорт/импорт зашифрованного бэкапа, автоблокировка.

## Как пользоваться

1. Откройте `password-guide.html` в браузере (двойной клик или перетащите в окно).
2. Создайте хранилище с мастер-паролем. **Пароль нигде не хранится** — забыли, всё потеряно.
3. Добавьте аккаунты и данные восстановления.
4. **«Экспорт»** — скачайте зашифрованный файл-бэкап `.json` и храните его отдельно от мастер-пароля. На новом ПК: откройте HTML → «Импорт» → выберите файл → мастер-пароль.
5. *(Опционально)* **«🌱 Seed-фраза»** — включите резервный доступ по 12 словам: на экране входа появится «🔑 Забыли пароль? Восстановить по seed-фразе». Фраза показывается один раз — запишите её и храните офлайн, как второй ключ от хранилища.

## Конфиденциальность данных

Приложение построено по принципу «данные не покидают устройство». В коде нет телеметрии, аналитики, трекеров и внешних ресурсов (все стили и иконки — инлайн, никаких CDN). Дополнительно стоит строгий CSP-meta: внешние скрипты/стили/шрифты запрещены, сетевые запросы разрешены только к самому приложению и к GitHub API (для «Проверить обновления»).

**Что приложение никогда не делает:**

- Не отправляет ваши пароли, логины, мастер-пароль или расшифрованные данные куда-либо.
- Не отправляет телеметрию, статистику использования или идентификаторы устройства.
- Не обращается к сторонним сервисам и не загружает внешние ресурсы (скрипты, шрифты, изображения).
- Не проверяет пароли на утечки и не отправляет куда-либо их хэши.
- Не хранит мастер-пароль: он нигде не сохраняется, ключ выводится локально (PBKDF2) и используется только в памяти браузера.

**Где живут данные:** только в `localStorage` вашего браузера, в зашифрованном виде (AES-256-GCM). Файл-бэкап `.json` создаётся локально и скачивается в вашу папку «Загрузки» — он не загружается ни на какой сервер.

**Единственные сетевые запросы в коде (по желанию, без ваших данных):**

- «ℹ️ О приложении» и «Скачать локальную копию» на веб-версии делают `fetch` к **собственному** файлу приложения и `./VERSION` на том же сайте — это запросы к самому приложению, в них нет никаких данных хранилища.
- Кнопка **«🔍 Проверить обновления»** в «О приложении» делает единственный внешний запрос — к GitHub API (`api.github.com`) за публичными данными о последнем релизе (версия и SHA-256), чтобы сравнить с вашим файлом. Никаких данных хранилища, паролей или мастер-пароля не отправляется.
- В локальной версии (`file://`) этих запросов нет вообще — приложение работает полностью офлайн.

**Когда данные всё же могут покинуть устройство — только по вашему действию:** если вы сами загрузите файл-бэкап в облако/репозиторий, или откроете веб-версию на чужом устройстве (тогда данные останутся в `localStorage` этого устройства). Приложение само ничего не отправляет.

## Веб-версия (GitHub Pages)

Страница на GitHub Pages — это то же приложение, раздаётся по URL: `https://volumorph.github.io/rearcovery/`.

⚠️ **Если используете веб-версию, понимайте риски:**

- Вы доверяете коду, который отдаёт сервер. Вводите мастер-пароль только на странице по этому адресу.
- Данные хранятся в `localStorage` браузера того устройства, с которого заходите. Не открывайте веб-версию на чужих компьютерах.
- Репозиторий публичный: в нём только код приложения, ваших данных там нет — но мастер-пароль остаётся единственной защитой.
- Всегда держите свежий `.json`-бэкап: очистка данных браузера = потеря хранилища.

Рекомендуемый режим: скачайте HTML из репозитория один раз и открывайте локально; веб-версия — для быстрого доступа на своём устройстве.

## Деплой

Деплой полностью автоматизирован через GitHub Actions (`.github/workflows/deploy.yml`); источник GitHub Pages уже настроен на ветку `gh-pages` — вручную ничего настраивать не нужно. Перед пушем правок в `src/` пересоберите файл:

```bash
npm run build
git add .
git commit -m "описание изменений"
git push origin main
```

Workflow сам: пересоберёт `password-guide.html` из `src/` и проверит, что он совпадает с закоммиченным (`git diff --exit-code`), прогонит тесты, посчитает SHA-256, обновит хэш в этом README, опубликует релиз `v1.0.N` и пересоберёт ветку `gh-pages`, которую отдаёт GitHub Pages.

## Для разработчиков

Устройство и правила работы описаны в `ARCHITECTURE.md` (внутренняя структура, модель данных, криптография, граф) и `AGENTS.md` (конвенции, обязательные проверки, частые точки правок). Исходники лежат в `src/` (`template.html`, `styles.css`, `js/*.js`) и собираются в единый `password-guide.html` командой `npm run build`; собранный файл коммитится как артефакт. Юнит-тесты запускаются командой `npm test` (см. `tests/`).
